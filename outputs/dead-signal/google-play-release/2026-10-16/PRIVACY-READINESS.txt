데드 시그널 Google Play 개인정보·제출 자료 독립 감사
작성일: 2026-10-16 (Asia/Seoul)
범위: 기존 Android 1.0.0(1) 출시 후보의 읽기 전용 검사와 개인정보 문서 파일 준비.
앱 소스, 네이티브 프로젝트, 바이너리, 사용자 저장 데이터, 실행 중인 8806 브라우저, 계정 및 호스팅은 변경하지 않았습니다. 서명·업로드·제출·출시 상태는 root가 별도 확인하는 작업이며 이 보고서가 완료를 증명하지 않습니다.

1. 확인된 Android 빌드와 데이터 처리

대상 패키지: kr.bottlecorp.deadsignal. 기존 AAB Manifest는 minSdk 24, targetSdk 36, versionName 1.0.0, versionCode 1입니다.
unsigned AAB: 184146374 bytes
SHA-256: 00526025686609890facf9d7cc28acd4c0f19e0b3a100ebfba5f3ecb7a626f4a
debug APK: 195587801 bytes
SHA-256: 3b56cfd1b04f6e38817005ee9e309ab28954a8e19c91b1c53c17bc3aaf2472c1
두 파일을 이번 감사에서 다시 해시하고 ZIP으로 읽었습니다. dist의 340개 파일은 AAB 및 APK에 각각 전부 포함되며 파일별 내용 해시 불일치가 0개입니다. 앱 변경 후 새 바이너리를 만들 경우 이 확인을 새 산출물에 다시 적용해야 합니다.

actual-aab-manifest.xml은 기존 bundletool 감사에서 실제 AAB를 추출한 결과입니다. 추가로 기존 debug APK를 aapt2 dump permissions로 직접 검사했습니다. 두 결과의 요청 권한은 자체 signature 권한 kr.bottlecorp.deadsignal.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION 하나입니다. INTERNET, AD_ID, BILLING, 위치, 연락처, 카메라, 마이크, 공유 저장소 권한은 없습니다. allowBackup=false, fullBackupContent=false, usesCleartextTraffic=false를 확인했습니다. ProfileInstallReceiver의 android.permission.DUMP는 해당 수신기를 보호하는 속성이며 앱이 요청한 추가 데이터 접근 권한이 아닙니다.

package.json은 Capacitor core/android/ios 8.5.3 및 App 8.1.2를 사용합니다. 광고·분석·추적·실제 결제 SDK는 연결되어 있지 않습니다. 이전에 작성한 AdMob/BM 설계 메모는 구현된 기능이 아닙니다.
server.url과 외부 allowNavigation은 설정되지 않았고 Android 로컬 앱 origin은 https://localhost입니다. 게임 코드, 93개 활성 디자인 자산 및 효과 이미지가 앱에 포함됩니다. production-art.js의 fetch는 로컬 assets/production의 메타데이터와 이미지 경로를 검사해 읽습니다. Capacitor 런타임에 범용 HTTP/Cookie API 코드가 있다는 이유만으로 게임이 외부 데이터를 전송한다고 판단하지 않았습니다. 반대로 이번 정적 검사를 실제 네트워크 패킷 캡처나 실기 동작 검증으로 표현하지 않았습니다.
storage.js는 dead-signal.profile.v1 키로 진행, 처치, 부품, 장비·강화, 설정 및 이어하기 기록을 localStorage에 저장합니다. 게임 계정·로그인·개발자 서버·클라우드 저장 동기화는 없고 개인정보 입력 폼도 확인되지 않았습니다. bundled mobile-privacy.js에는 기기 내 기록, 개발자 서버 전송 없음, 로컬 삭제, OS/스토어 처리 범위를 설명하는 한국어 텍스트가 있습니다. 앱 내 문의 안내는 스토어 개발자 연락처를 가리키며 새 공개 메일을 바이너리에 직접 넣지는 않았습니다.

2. 운영자·지원 연락처와 공개 정책 준비

공식 Google Play의 같은 개발자 INK Chat 공개 페이지에서 개발자 이름 '주식회사 바틀'과 개발자 이메일 alphameet.official@gmail.com을 독립 확인했습니다. root는 동일 조직 계정에서 새 게임의 운영 주체와 공개 문의 주소로 사용하도록 요청했습니다. 이는 해당 주소의 실제 수신·응답 시험이나 문의 보관 운영 검증을 뜻하지 않습니다. 다른 제품 지원 주소 help@inkchat.ai는 재사용하지 않았습니다.
확인 페이지: https://play.google.com/store/apps/details?id=com.bottle.ink&hl=ko

출시 정책 기준 파일 (canonical): privacy/privacy-policy.ko.html
운영 미확정 사항: privacy/PUBLICATION-NOTES.txt
기존 검토 이력은 내부 보존용이며 게시 대상에서 제외합니다. 이 감사와 운영 노트도 공개 정책 본문과 구분합니다.

새 HTML은 회사명과 확인된 공개 이메일, 앱 자체의 수집·전송 없음, 기기 내 게임 저장·삭제, 계정 없음, OS·스토어 범위 및 자발적 이메일 문의를 설명합니다. 앱 서버에 보유하는 개인정보가 없다는 사실과 별도 문의 메일을 구분했습니다. 문의 보관 기간, 삭제 책임자, 종결 후 삭제 시점이나 법정 예외를 임의로 만들지 않았습니다. 검토용 본문에는 초안 표시를 남기지 않았으며 미확정 운영 항목은 별도 노트에 명시했습니다. 문서 작성일은 시행일 확정이 아닙니다.
HTML은 JavaScript, 폼, iframe, 원격 리소스 없이 구문 검사를 통과했습니다. 실제 공개 HTTPS URL, 익명·모바일 접근 및 렌더링은 이 감사에서 검증하지 않았습니다. root는 별도 support 전용 GitHub Pages 저장소 niceverygood/dead-signal-support를 검토 중입니다. 이 기록은 저장소 생성·Pages 활성화·URL 접근 완료를 의미하지 않으며, 이 로컬 파일 자체는 공개 정책 URL이 아닙니다.

아직 확정/검증할 항목:
- 이메일 문의의 실제 보유 기간 또는 목적 종결 시 삭제 기준, 실행 책임과 예외 대상·근거·기간.
- 문서 시행일과 새 게임 지원 운영 담당 체계. 공개 주소는 확인했으나 응답 체계는 미확인입니다.
- 로그인·지역 제한 없이 읽을 수 있는 공개 HTTPS 정책 URL. PDF나 사용자가 편집 가능한 문서 URL은 제출용으로 사용하지 않습니다.
- 새 앱의 Store settings 지원 이메일과 개인정보 URL 저장 값. 기존 listing.json은 이 필드의 실제 Console 저장 완료를 증명하지 않습니다.
- 게시한 HTML 내용, 앱 내 설명, 데이터 안전성 신고의 일치. 현재 앱이 수집/공유하지 않는다는 신고는 현재 버전 기준이며 광고·분석·결제 추가 시 재검토가 필요합니다.

Google Play는 데이터 수집이 없는 앱에도 공개 개인정보 문서와 앱 내 안내를 요구합니다. 정책에는 운영 주체·연락처, 정보 처리와 보유·삭제 설명이 필요합니다. 공개 연락처를 찾았다는 사실만으로 모든 운영 정책이 확정된 것은 아닙니다.

3. 실제 게임 화면과 런타임 제출 증거

기존 store 폴더의 512px 앱 아이콘, 1024×500 feature graphic은 준비된 마케팅 자산입니다. 생성형 이미지나 무드보드를 실제 게임 스크린샷으로 취급하지 않았습니다. 기존 store 산출물만으로 실제 Android 앱의 플레이·오디오·멀티터치·배경 복귀를 검수했다는 증거는 없습니다. 웹 브라우저 검수 결과는 네이티브/실기 검수와 구분해야 합니다.

Play 스토어 게시용 일반 최소 조건은 기기 유형 전체에 걸쳐 스크린샷 2장입니다. JPEG 또는 알파가 없는 24bit PNG, 각 변 320~3840px, 긴 변은 짧은 변의 2배 이하여야 합니다. 게임 추천 영역 자격 안내의 '16:9 가로 1920×1080 이상 3장 또는 9:16 세로 1080×1920 이상 3장'은 일반 2장 최소 조건과 구분됩니다. 게임 자체의 실제 경험을 캡처해야 합니다.
원칙적으로 현재 제출할 Android 후보를 전용 QA 환경에서 실행해 메뉴와 실제 플레이 화면을 확보하고, 원래 캡처 및 화면 크기를 기록해야 합니다. 아이콘·feature graphic·웹 캡처만으로 실제 네이티브 UI 검증 완료를 주장할 수 없습니다. 현재 기존 기록에는 CUA 네이티브 앱 연결 불가, 실기 UI 미검증, 16KB 페이지 크기 기기에서의 런타임 미검증이 남아 있습니다. 파일 정렬 검사/빌드 성공은 해당 런타임 검증의 대체가 아닙니다. root가 별도 수행하는 새 QA가 있다면 그 증거로 상태를 갱신해야 합니다.

4. 별도 iOS 결함 발견 (Google Play Android와 구분)

iOS config의 iosScheme은 capacitor이고 로컬 base는 capacitor://localhost/assets/production/입니다. dist/production-art.js assetURL 함수에는 두 호환 문제가 있습니다. custom scheme의 url.origin은 'null'이므로 380행의 new URL(decoded, url.origin) 정규화가 실패할 수 있고, 382행의 http:/https: 허용 목록도 capacitor:를 거부합니다. 실제 productionManifest를 전달한 순수 Node 소스 probe에서 survivor-shotgun-idle 로드가 invalid-asset-path로 실패하고 fetch 호출은 0회였습니다. 동일 코드를 https://localhost/assets/production/ base로 실행하면 fetch 단계에 도달했습니다. 이 문제는 소스 수준으로 재현된 iOS 자산 경로 호환 결함입니다. Android의 https 로컬 origin은 이 특정 검사에 의해 막히지 않습니다. 전체 iOS 화면 영향은 네이티브 UI에서 직접 관찰하지 않았고 코드나 빌드를 수정하지 않았습니다. iOS의 이전 빌드 성공은 실제 플레이 가능 증거가 아닙니다. 세부 재현과 향후 수정·검증 계획은 IOS-ASSET-PROTOCOL-ISSUE.txt에 기록했습니다.
