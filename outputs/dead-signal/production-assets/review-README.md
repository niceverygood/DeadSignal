# DEAD SIGNAL 프로덕션 검수 갤러리

`review.html`을 열면 무드보드, 정면·후면 제작 입력, 실제 모델의 원본 미리보기, 게임 카메라로 렌더한 스프라이트를 비교할 수 있습니다. 방향 슬라이더와 동작 메뉴로 실제 프레임을 확인하고, 입력 이미지나 실행 캡처는 클릭해 원본 크기로 확대합니다.

갤러리는 선택한 스프라이트만 불러옵니다. GLB를 브라우저에서 새로 렌더하거나 외부 생성 API를 호출하지 않습니다. 모든 이미지는 기존 원본 파일을 그대로 표시합니다.

게임 등록 표시는 현재 게임의 `production-manifest.js`에 연결되어 있으며 게임 파일과 출력 PNG·metadata의 SHA256이 일치한다는 뜻입니다. 제작 이력의 다른 모델 버전까지 시각적 최종 승인을 받았다는 뜻은 아닙니다. 화염병은 실제 모델과 스프라이트 납품물로 표시하며 별도 병 투사체 entity에 연결된 것으로 표시하지 않습니다.

현재 파일 상태를 다시 반영하려면 워크스페이스 루트에서 실행합니다.

```sh
node work/build-production-review.mjs
node --test work/production-review.test.mjs
```

빌더는 현재 게임 카탈로그와 실제 존재하는 입력·모델·native 출력·QA 파일을 읽어 `review-manifest.json`, `review-data.js`를 갱신합니다. 게임 코드와 원본 이미지는 수정하지 않습니다.

현재 등록 native atlas는 93개입니다. 원화 35의 지면 화염과 원화 05의 폭발을 별도 image_gen VFX 2개로 표시하며, Meshy/native 93개에 더하거나 GLB에서 생성한 것으로 표시하지 않습니다. 실행 화면 메뉴에서 재가공하지 않은 16프레임 원본 PNG, 원화, 최신 화염·폭발 QA 캡처, 원본 픽셀 분석과 브라우저 진단 JSON을 볼 수 있습니다. 초기 소형·5개 불꽃 배치 캡처도 제작 이력으로 보존하므로 최종 9개 배치 캡처와 구분해 읽습니다.

화염 최종 캡처는 명시적 승인 목록의 플레이어 모바일, 8탄 중간·최종보스 9개 배치, v0.24 플레이어 0.5초 장면만 표시합니다. helper 기대값 오류가 남았던 `fire-player-nine-half-v023.png`는 제외하며, 새 `fire-player-nine-half-v024.png`와 실제 진단 `fire-player-final-browser-v024.json`을 연결합니다. 초기·캠페인 이력 캡처에는 최종 VFX 검수 근거가 아니라는 표시를 붙입니다.

갤러리의 데이터·스크립트·스타일 링크에는 빌더가 현재 파일 해시 질의를 붙입니다. 다시 빌드한 뒤 갤러리를 새로고침하면 최신 집계와 캡처 목록이 반영됩니다.

폭발은 실제 shockwave 수명 .32초의 1회 재생입니다. 단일 damage0 시각 검사와 기존 차량·드럼통 실제 3연쇄를 구분하고, 기본 8상태·프레임 10/일시정지 3상태·390px DPR2 진단을 연결합니다. 최종 검수에 쓰지 않는 initial/cache-stale/capture-transient 파일은 일반 QA 목록에서 제외하며 기존 보스 모델 후보 이력은 명시된 비교로 보존합니다.

v0.25 생존자 걷기·뛰기 개선은 [MOTION-HANDOFF-v025.txt](MOTION-HANDOFF-v025.txt)에 적용 범위와 한계를 정리했습니다. 실제 걷기 자세·원본 주기에 맞춘 제한 재생·기하 높이 기반 접지 보정, 달리기 공중 구간 유지, 이동 진단 JSON 6개와 원본 GLB 3D 측정 자료를 안내합니다. 최종 접지·모바일 캡처는 실행 화면 목록에 표시하며, 뷰포트 아래 빈 영역이 포함된 초기 walk-candidate 캡처는 워크스페이스의 별도 비교 폴더로 분리했습니다. 정확한 양발 고정이나 지형 대응 foot IK를 구현한 것으로 표기하지 않습니다.
