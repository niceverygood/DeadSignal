Critical findings:
P1 all-final-boss-static: All 12 final boss source GLBs have zero skins and zero animation clips. Runtime contains 16 directional views of one rest pose; movement visually slides that unchanged pose. Gallery native-integrated means source artwork installed, not complete animation.
P1 state-animation-missing: ProductionPoseClock/actorFrame choose only idle/walk/run/dash from travel. Boss attackState, windup, charge, recover and skill state never choose body clips. Native hero fire/reload also do not change body pose. Hit reaction is a same-sprite screen flash.
P1 boss-death-identity-lost: engine.killEnemy saves corpse type but drops bossKey, radius, source asset and pose. drawCorpse uses generic Canvas body by enemy type, so native appearance vanishes at death. Final boss victory ends immediately; there is no dying/death clip.
P2 walk-only-low-sampling: All 12 mid bosses and 7 enemy types have real 24-joint walk deformation, but only 8 sampled poses per direction and no alternate native clips. Hero has32 walk/run samples; idle remains one pose. Merely increasing sample count will not create missing actions.
P2 enemy-gait-speed-and-grounding: Enemy and boss use engine distance-driven walkPhase (0.08 rad/world-unit); one cycle is 78.54 world units regardless of scale/anatomy. Only hero gets measured gait duration and sole height correction. Enemy/boss footing and stride synchronization require actual source pose measurement, not whole-sprite bounce.
